## 2. 重要な決定と、その理由

あとから「なぜこうなっているのか」を掘り返さなくて済むように、判断の理由まで残す。

### 2-1. 盆栽・霧・四季をすべて止めた（`src/lib/features.ts`）

```ts
export const SHOW_BONSAI = false;     // 盆栽
export const SHOW_KIRI_GLOW = false;  // 序の霧
export const ENABLE_SEASON = false;   // スクロール連動の四季
```

**経緯**: 盆栽GLB 3点を最適化して 3D 化まで実装したが（F02/F03）、実機確認で「サイトの質感を下げている」と社長判断 → 静止画へ戻す → それでも不自然として非表示へ。
続いて序の霧（緑がかったもや）も不要と判断。

**連鎖に注意**: `--season-glow` を参照していたのは霧だけ、`--season-beam` を参照していたのは盆栽だけだった。
両方消した時点で**四季を映す面がゼロ**になり、計算だけが走る状態になったため四季も停止した。

**戻し方**: 該当フラグを `true` にするだけ。実装は消していない。
ただし盆栽を戻すなら**縦長（158:248）の素材**が要る。手持ちの GLB は写真から起こした浮き彫り板で、正方形素材を切り出すと構図が壊れる。

### 2-2. 盆栽GLB は「3Dモデル」ではなかった

`bonsai_model/` の3点は ImageToStl.com が**写真1枚から起こした浮き彫り板**（100×100 に対し厚み9）。
角度違いの3ファイルは同一物体の別視点ではなく**独立した別々の板**で、統合は原理的に不可能。設計書 F02 の前提が成立しない。

最適化自体は成功している（正面 37.0MB → 286KB）。手順は `scripts/optimize-bonsai.sh`、詳細な罠は
Obsidian `dev-knowledge/2026-09-16-photogrammetry-glb-web-optimization.md`。

### 2-4. 配色に「面ごとの明度変種」を足した（T27）

TOKENS.md の原色は乗せる面を区別していないが、実測すると読めない組み合わせがあった。
色相と彩度比は保ったまま明度だけ動かして基準を満たす値を算出した（社長承認済み）。

| トークン | 値 | 用途 | 実測 |
|---|---|---|---|
| `--matsuba-on-dark` | `#679f75` | 墨面の現在地・成功文 | 4.57 |
| `--matsuba-on-kinari` | `#44694d` | 生成面の現在地 | 4.52 |
| `--shinshu-on-dark` | `#f26455` | 墨面のエラー文・落款 | 4.52 |

原色（`--matsuba-bright` / `--shinshu`）は残してある。生成面の欧文ラベルと技能目盛りは原色の真朱で 5.51 と合格しているため。

**色を触ったら `npm run check:contrast` を必ず流す。** 背景を決め打ちせず、実際に配信している木目画像の明るい側5%に墨48%を重ねた合成色を毎回計算する。21項目、不合格があれば非0終了。

### 2-5. 我（About）の縦書きは左端・句読点なし

- `xl` 以上で `w-full` にしていたため、`vertical-rl` が右端から流れる性質で文字がカラム右端に張り付き、ブロックが軒並み右寄りに見えていた → 全幅 `w-fit` に統一
- 縦書きに読点を打つと1文字分の空きが行の途中に出て流れが切れ、短い3行に句点まで付くと文章の断片に見える → **日本語のステートメントは句読点なし**

### 2-6. 木目背景の解像度

`object-cover` で全画面に敷くため、**縦長の画面では「画面高 × 1.887」まで拡大される**。
iPhone 縦(390×844 DPR3) で必要な実ピクセル幅は **4778**。

- `sizes="(max-aspect-ratio: 1887/1000) 189vh, 100vw"`（`100vw` では 1/4 しか要求せず4倍に伸びていた）
- `next.config.ts` の `deviceSizes` に `5120` を追加（既定上限 3840 では頭打ち）
- 生成解像度は元素材の原寸 **4680×2480**。これが上限で、素材を作り直さない限り上がらない
- 品質は既定の 75。90 との差は実測で平均 0.4%/256 しかなく、墨48%を重ねるため視認できない（392KB → 211KB の差は割に合わない）

素材を差し替えたら `node scripts/prepare-images.mjs` で再生成する。

### 2-7. 縦書きの「ー」が横棒だったのはフォントのサブセットが原因

サブセット時に OpenType 機能を全部落としていた（`--layout-features=`）ため、縦組みで
**長音符が横棒のまま、全角括弧の向きと読点の位置も崩れていた**（社長指摘・2026-09-20）。

長音符 U+30FC はカタカナブロックにあり Unicode の Vertical_Orientation が「直立」なので、
ブラウザは回してくれない。**縦組みの字形はフォント側の `vert`/`vrt2` が字形ごと差し替えて作る。**
`scripts/subset-jp-fonts.mjs` の `LAYOUT_FEATURES = 'vert,vrt2'` がこれを担保する。**空にしないこと。**

代償は 3 書体合計 +19KB（98KB → 117KB）。縦組みの正しさと引き換えに払う判断。

あわせて `body` に `line-break: strict` を入れた。既定の `auto` は小書き仮名（ャ ュ ョ ッ）と
長音符が行頭に来るのを許し、狭い段で「リニ／ューアル」のように割れていた。

### 2-8. 我（About）の紹介文から「（休学・フリーランス専念）。」を削除

社長判断（2026-09-20）。`dictionary.ts` の `about.bio` から該当句を落とし、
**EN 側の同じ文（`on leave to focus on freelance work`）も揃えて削除**した（片方だけ残すと同じ情報が英語で出てしまうため）。

- 300px の段では「在学／中。」と最終行が1文字+句点になる。文言を詰めるかは社長判断
- **歴（Career）には「同理由により大学を一年休学」が残っている**（`content/career.ts`）。
  休学を出したくない意図なら、ここも直す必要がある。今回は指示範囲外として触っていない
- **EN の紹介文は本文書体（Zen Kaku Gothic New）にした**（社長判断・2026-09-20）。
  Yuji のサブセットは和文から起こした英字（`AIOSTWbei` `0247`）しか持たず、EN では
  宣言済みの字だけ筆文字・残りがシステムのサンセリフになり**単語の途中で書体が変わっていた**
  （"Technology" の T だけ筆文字）。ASCII 全域を足す案もあったが、筆書体は英文の本文組み用ではない
- **紹介文カラムを 300px → `sm:320px` / `xl:380px` に広げた**（社長指示「1行にまとめて。文字は小さくしないで」）。
  本文は `clamp(15px,1.1vw,17px)` で伸びるのにカラムが固定だったため必ず2行に割れ、

  **文字サイズは一切変えずに** 540px 以上で1行に収まる。**この2値を縮めると2行に戻る**
  - `xl` 未満で 380px にしないのは、1024px 幅だと写真(416)+gap(36)+段 が入りきらず段落ちするため（実測上限 364px）
  - **スマホ（〜430px）は1行にできない。** 左の縦ナビが 96px 固定で、390px 端末では本文に 246px しか残らず、
    1行にするには 12px まで縮める必要がある（社長の「小さくしないで」に反する）。→ 3-4

  あわせて `subset-font.sh` にも残っていた `--layout-features=''` を `vert,vrt2` に直した
  （2-7 と同じ罠。筆文字は現状すべて横組みか一文字だが、縦組みに使った瞬間に破綻するため先に塞いだ）。
  差引 24.7KB → 25.7KB

### 2-9. 縦ナビはスマホでだけ 56px に絞る

社長判断（2026-09-20）。**`sm`(640px) 未満のみ 96px → 56px。PC・タブレットは一切変えない。**

96px は 390px 端末で画面の約25%を占め、左余白 120px（ナビ+24px）と右 24px を引くと本文に 246px しか
残らなかった。ナビの中身（ロゴ「麟」44px・ラベル列 37px）は実測 44px あれば足りる。

値は `tokens.css` の `@media (width < 40rem)` で `--nav-w` を上書きする**1箇所だけ**。
`@theme` の `--spacing-nav` が `var(--nav-w)` を参照しており、`w-nav` も
`pl-[calc(var(--spacing-nav)+24px)]` も使用時に解決されるため、縦ナビ・全セクションの左余白・
序の ScrollCue がまとめて追従する。

効果（紹介文の2文目が1行に収まるか）:

| 幅 | 段幅 96px時 → 56px時 | 1行に必要 308px |
|---|---|---|
| 320 | 216 → 216 | 届かない（左余白は元々 pl のみ） |
| 360 | 246 → 256 | 届かない |
| 375 | 261 → 271 | 届かない |
| 390 | 246 → **286** | 文1のみ1行に。文2は端行が1割残る |
| 414 | 270 → **310** | **✅ 2文とも1行** |
| 430 | 286 → **326** | **✅ 2文とも1行** |

**副作用を1つ潰した**: 言語切替「EN / JP」は `w-nav` に収めているため、56px のレールでは
`gap-2.5` のままだと 70px になり罫線を 7px 跨いだ。`gap-0.5`（`sm` 以上は従来どおり）で 53px に収めた。
**字間は詰めないこと** ─ 一度 `tracking-normal` にしたらボタンの当たり判定が 20px → 14px に痩せた。

| 320 | 216px | 92px | 10.5px |

**社長の「あまり小さくしてほしくない」に反するため文字は縮めていない。**
390px では文1は1行に収まり、文2だけ端行が1割残る状態。

やるなら選択肢は2つ。どちらも社長判断が要る。

1. `sm` 未満だけ本文を可変にする（例 `clamp(13px, calc(4.87vw - 5.07px), 15px)`）。
   375px 以上が1行になる代わりに、**文言を変えるたび係数の計算し直しが要る**（壊れても豆腐にならず気づきにくい）
2. 文言を短くする（「システム理工学部」を省く等）。係数を持たずに済む

- **three.js 一式が未使用のまま残っている**。`three` / `@react-three/fiber` / `@react-three/drei` と GLB 3点（1.5MB）、Draco デコーダ（745KB）。盆栽を完全に諦めると決まったら削除でリポジトリが約2.3MB軽くなる

- **外部リンクの `↗`（U+2197）はどの自前フォントにも無い**。Shippori / Zen / JetBrains Mono すべて未収録で、システム書体に落ちる（macOS では Hiragino Kaku Gothic）。結の外部リンクが以前から同じ挙動で、作の短冊でも踏襲した。豆腐にはならないが自前の書体では出ない

## 5. 開発コマンド

```bash
npm run dev                      # 開発サーバー
npm run dev -- -H 0.0.0.0        # 実機確認用（http://192.168.0.18:3000）
npm run build && npm run start   # 本番ビルドの確認
npm run lint                     # ESLint
npm test                         # vitest（季節の純粋関数 8件）
npm run check:contrast           # 配色のコントラスト実測 21項目（色を触ったら必ず）
node scripts/prepare-images.mjs  # 新素材/ から配信用 WebP を再生成
npm run bonsai:optimize          # 盆栽GLBの最適化（使う場合のみ）
npm run font:measure             # 和文フォントの使用文字を実サイトの DOM から実測（要: build + start）
#   ↑ 文言を足したら必ず流し直す。忘れるとその文字だけシステム書体になる（2026-09-20 に実際に踏んだ）
npm run font:subset:jp           # 実測した文字集合で和文フォントを再生成（venv なら PYTHON=... を前置）
```

### 踏み抜きやすい罠

- **`--font-*` に書体名を直書きしない。** next/font の `@font-face` は family をハッシュ名（`shippori` / `yuji` / `zenKaku`）で生成する。`tokens.css` の素の `:root` は `globals.css` の `@theme`（Tailwind のテーマレイヤー）**より後ろ**に出力されるため、直書きするとカスケードで勝ってしまい、一致しない名前が最終値になる。**和文3書体がまるごと効かなくなる**。必ず `var(--font-shippori, '...')` の形で書く
- 欧文2書体（Marcellus / JetBrains Mono）は next/font/google が本来の family 名を保つため偶然一致する。**欧文が出ていても和文が効いている証拠にはならない**
- `git push` は `git config http.postBuffer 524288000` を設定済み。未設定だと HTTP 400 で落ちる
